# Pumpkin Friends in-game: Minecraft API evidence (spike S0)

Status: evidence (2026-10-03, extended 2026-10-04 by D2). Output of spike **S0** of `INGAME.md` (11.2, 4.3, Appendix B item 9); D2 added the members package U1 had to verify ad hoc (`PauseScreen#showsPauseMenu`, `Checkbox.Builder#maxWidth`, `FriendToast#add`, `ResolvableProfile#createUnresolved`) to `members/ingame.txt` and re-ran the probe and the report for all 24 versions. Nothing here is a guess: every descriptor was read from the real client jar of the version and translated with Mojang's own mapping file; every loader statement links to the source or artifact it was read from. What could not be proven is listed in section 8.

Tool and raw data: `tools/mc-api-probe/` (re-runnable, section 1). The tables below are generated by it (`report --doc`); do not edit them by hand.

## 0. Findings in one page

1. **11 API runs between 1.20 and 26.3.** Inside a run no Minecraft member the mod uses changes its signature; between two runs at least one does (section 4). Runs: 1.20-1.20.1 · 1.20.2 · 1.20.3-1.20.4 · 1.20.5-1.21.1 · 1.21.2-1.21.5 · 1.21.6-1.21.8 · 1.21.9-1.21.10 · 1.21.11 · 26.1-26.1.2 · 26.2 · 26.3.
2. **Recommended node list: 19 nodes** (11 Fabric, 7 NeoForge, 1 Forge), explicit release ids, `javaMin`, loader minimum (section 5). Every id was checked against the Mojang manifest (`check-nodes`).
3. **Java:** Mojang requires 17 up to 1.20.4, 21 for 1.20.5 to 1.21.11, 25 from 26.1 (version JSON `javaVersion`; class files of the client jars are major 61, 65, 69).
4. **Render rewrite:** `GuiGraphics` returns `int` from `drawString` up to 1.21.5 and `void` from 1.21.6 (a binary break although the source compiles); `fill` switches to render pipelines at 1.21.6; 26.1 replaces `render(GuiGraphics, ...)` by `extractRenderState(GuiGraphicsExtractor, ...)` and the `Screen`/widget render methods follow.
5. **Input rewrite at 1.21.9:** `keyPressed(int,int,int)` becomes `keyPressed(KeyEvent)`, mouse and character callbacks take event records. `Screen.init(Minecraft,int,int)` loses its `Minecraft` parameter at 1.21.11.
6. **26.2 moves `setScreen`, the current screen and the toast manager from `Minecraft` to `Gui`**; 26.2 also adds `unpublishServer`, 26.3 changes `publishServer` again.
7. **Fabric hook:** `PauseScreen#init()` is declared in `PauseScreen` itself on all 24 probed versions. On obfuscated versions (1.20 to 1.21.11) the Mixin target at runtime is `net.minecraft.class_433#method_25426` (identical on all of them); from 26.1 there is no intermediary and the target is the Mojang name.
8. **NeoForge / Forge hook:** `ScreenEvent.Init.Post` exists and is posted on the game bus (`NeoForge.EVENT_BUS` / `MinecraftForge.EVENT_BUS`) in every NeoForge series from 21.0 to 26.3 and in Forge 1.20.1-47.4.0 and 47.4.26 (section 6).
9. **Mojang ships its own friends system from 26.2** (`FriendsOverlayScreen`, `FriendToast`, `FriendsButton`, toast id `FRIEND_SYSTEM_NOTIFICATION`). It is absent in 26.1.2. INGAME risk 8 is real.

Contract problems found in `INGAME.md` are in section 7 (7 items, each with the minimal change proposed).

## 1. Method and how to re-run

1. The version list is the Mojang version manifest (`piston-meta.mojang.com/mc/game/version_manifest_v2.json`). All 24 requested releases exist: 1.20, 1.20.1 to 1.20.6, 1.21 to 1.21.11, 26.1, 26.1.1, 26.1.2, 26.2, 26.3 (1.20.3, 1.21.3 and 1.21.7 were added to see where a point release changes things). Nothing from the requested list is missing.
2. For each version the tool downloads `client.jar` and `client_mappings` (the official Mojang mapping file) from the manifest entry, checks the SHA-1, and keeps both outside the repository. Versions from 26.1 on are unobfuscated and publish no mapping file.
3. `javap -p -s` reads the classes (JDK 25 reads all of them), the mapping file translates class, method and field names back to Mojang names, and members are resolved through the class hierarchy (superclasses and interfaces), so an inherited method is reported with the class that declares it.
4. `members/ingame.txt` lists what the compat layer needs. A line marked `@used` is called or overridden by the mod; only those decide node boundaries (section 4).
5. `code` reads what a vanilla method calls (`javap -c`), which is how the "how vanilla does it" recipes (section 3.2) were obtained.

```
node tools/mc-api-probe/cli.mjs probe --version 1.21.1 'PauseScreen#init' 'Screen#render' 'Button#builder'
node tools/mc-api-probe/cli.mjs probe --version 26.3   'PauseScreen#init' 'Screen#extractRenderState'
node tools/mc-api-probe/cli.mjs collect 1.20 1.20.1 ... 26.3          # all versions, writes results/<id>.json
node tools/mc-api-probe/cli.mjs report --doc docs/friends/INGAME-API.md
node tools/mc-api-probe/cli.mjs check-nodes
cd tools/mc-api-probe && node --test
```

Setup details (cache folder, JDK) are in `tools/mc-api-probe/README.md`.

## 2. Reading the tables

Section 3 has one table per member group. Columns are **eras**: consecutive versions in which every member of the group has the same signature. A cell shows `access (parameters) → return type`; `=` means the same as the column to the left; `–` means the member does not exist; `class absent` means the class does not exist in that era. `← X` names the superclass or interface that declares an inherited member. Private members are left out. Types are shown by simple class name; the full descriptors with fully qualified Mojang names are in `tools/mc-api-probe/results/<version>.json` and are printed by the `probe` command.

The binary descriptor includes the return type. A call compiled against `int drawString(...)` throws `NoSuchMethodError` on a version where the method returns `void`, so return-type changes count as breaks.

### 3.1 Notes on the tables

- **`Screen#init`:** `protected void init()` is the override point in every era. `Screen.init(Minecraft,int,int)` (public final, called by the game) became `init(int,int)` in 1.21.11; the mod never calls it.
- **`Screen#resize`:** vanilla re-runs `init()` (through `rebuildWidgets`) on every window resize, or `repositionElements()` once the screen is initialised. Overriding `repositionElements()` and `rebuildWidgets()` is signature-stable in all 24 versions, overriding `resize` is not (it loses its `Minecraft` parameter in 1.21.11). INGAME 6.5 should override neither `resize` nor the two-argument `init`.
- **`Screen#mouseScrolled`:** three parameters up to 1.20.1, four from 1.20.2 (horizontal delta added). A scroll override is a node boundary at 1.20.2.
- **Toasts:** up to 1.20.2 the toast id is the enum `SystemToast.SystemToastIds` (use the constant `PERIODIC_NOTIFICATION`; no own id possible). From 1.20.3 `SystemToast.SystemToastId` is a class with public constructors (`()` and `(long displayTime)`), so the mod can own one id. From 1.21.2 the manager is `ToastManager` (`Minecraft.getToastManager()`), from 26.2 `Gui.toastManager()`.
- **`Checkbox`:** no builder in 1.20 to 1.20.2 (constructor only). The builder exists from 1.20.3.
- **`EditBox`:** the six-argument constructor `(Font,int,int,int,int,Component)` exists in all 24 versions; the other constructors are additions.
- **Scrolling list (vanilla `AbstractSelectionList`):** its constructor, render method, scroll methods and entry render method change in almost every era (rows of that group). This is the evidence for INGAME 4.4: do not use it; scroll through own widgets and `mouseScrolled`.
- **Mojang friends (26.2+):** `FriendToast`, `FriendsButton`, `FriendsOverlayScreen`, `SystemToast.SystemToastId.FRIEND_SYSTEM_NOTIFICATION` appear in 26.2 and are absent in 26.1.2. Our pause-menu button and title-screen button must be placed by free space, not by fixed slots (INGAME 6.1 already says so).
- **D2 additions (2026-10-04).** `PauseScreen#showsPauseMenu` exists from 1.20.2 and is `@used`: its first appearance lands on the existing 1.20.1 → 1.20.2 boundary, so the run list is unchanged. `Checkbox.Builder#maxWidth` exists from 1.21 only and stays context, **not** `@used`: marking it used would split the 1.20.5 – 1.21.1 run, and U1 ended up not calling it at all (the widget kit sizes its toggles itself, `mod` commit 0c339de). `FriendToast#add` (static, `ToastManager, Font, ResolvableProfile, Component`, 26.2+) and `ResolvableProfile#createUnresolved` (`String` or `UUID`, from 1.21.2) resolve on every version that has them and are context for INGAME A10 (the mod never reuses Mojang's friends toast); the tables show `class absent` / `–` where they do not exist.

**Unpublish** (`IntegratedServer.unpublishServer()`, returns `boolean`) exists **only from 26.2**. Before that vanilla has no way to close a published LAN world short of leaving it (section 7, item 2).

**Connect:** `ConnectScreen.startConnecting(Screen, Minecraft, ServerAddress, ServerData, boolean)` up to 1.20.4; a sixth parameter `TransferState` from 1.20.5 (pass `null`). `ServerData(String,String,boolean)` up to 1.20.1, `ServerData(String,String,ServerData.Type)` from 1.20.2 (`ServerData.Type.OTHER`).

- **Ids:** `<highest release id of the node>-<loader>`, e.g. `1.21.1-fabric` for 1.20.5 to 1.21.1. Unique per loader, no semver-prerelease shape problem for the node-id question of S1 (nothing parses it).
- **`minecraft`:** exactly the releases of one API run (section 4) that the loader supports. No ranges, no snapshots.
- **`javaMin`:** the lowest Java Mojang requires for any release in the node (version JSON `javaVersion.majorVersion`; `check-nodes` rejects a higher value).
- **Fabric `loaderMin`:** the highest loader floor among the first Fabric API builds of the node's releases (`fabric-floor`: the first `fabric-api` build for a Minecraft version declares the loader it needs). Cross-check with the bundled ASM (loader profile at `meta.fabricmc.net`): ASM 9.9, needed for the 26.x class files (major 69), first ships in loader 0.17.3; ASM 9.6, enough for the Java 21 class files (major 65), is bundled from 0.14.23 on; the Java 17 class files (major 61) of 1.20 to 1.20.4 need nothing newer than 9.2.
- **NeoForge `loaderMin`:** the first non-beta build of the lowest series in the node. NeoForge series follow Minecraft (`21.1.x` = 1.21.1, `26.2.0.x` = 26.2). Minecraft releases that only have `-beta` builds are **left out** (INGAME 2.2 rule, section 7 item 5): 1.21.2, 1.21.6, 1.21.7, 1.21.9, 26.1, 26.1.1, 26.3.
- **NeoForge strategy:** `fmlMavenRoot` for FML 4 to 9 (NeoForge 21.0 to 21.8), `fmlModFolders` from FML 10 (21.9+, 26.x), as INGAME 3.5 says. FML versions per series were read from the NeoForge POMs (21.1: 4.0.x, 21.3: 4.0.29 to 5.0.8, 21.4: 6.x, 21.5: 6.x to 7.x, 21.8: 9.0.x, 21.10 and 21.11: 10.0.x, 26.1.x and 26.2: 11.0.x, 26.3: 12.0.x).
- **Forge:** only 1.20.1 (47.x), `loaderMin` 47.4.0 because that is the version whose source was read for the `fmlMavenRoot` claim and the hook.
- **Not in the list** (INGAME 1.2 / 2.3): Forge above 1.20.1, NeoForge 20.x, Quilt, Minecraft below 1.20.

Possible merges (fewer jars, more risk): 1.21.9-1.21.10 and 1.21.11 differ in `Screen.init`, `PauseScreen.init` and `KeyMapping.Category.register` only; 1.20.1/1.20.2 differ in `mouseScrolled`, `renderBackground`, `ServerData`, `disconnect`. A merge needs reflection or `MethodHandle` for those calls and is not recommended before R-B.

## 8. What stayed unverified

- **Nothing was compiled or run.** All Minecraft evidence is class-file level (descriptors and call sequences). That a run really compiles against both of its ends is the U1/V* compile-matrix step; whether a node starts in a real game is S1/S2.
- **The `@used` list is an estimate.** It is derived from INGAME 4 to 7 and the vanilla recipes above. A member the mod ends up using that is not marked can add a boundary; a marked member the mod does not use can remove one.
- **Fabric `loaderMin`** comes from Fabric API's own loader floors and from bundled-ASM Java support, not from starting a game on the lowest loader. S1/S2 must smoke each node on its `loaderMin`.
- **NeoForge `loaderMin`** is the first non-beta build of the lowest series in a node. Betas of later series inside a node (for example 21.4.x before 21.4.121) are not excluded by the number and are untested.
- **Injection strategies** (`fmlMavenRoot`, `fmlModFolders`) are copied from INGAME 3.5. S0 only associated them with the FML version of each series; no game was started. In particular `fmlModFolders` on FML 11 and 12 (26.1 to 26.3) and `fmlMavenRoot` on FML 5 to 9 are untested.
- **NeoForge/Forge runtime names:** NeoForge 21.x and 26.x run Mojang names and Forge 1.20.1 runs SRG names (`m_91152_`, seen in the Forge patch); the reobfuscation settings of the node builds were not checked.
- **Hook behaviour in a running game** (the button appears, positions, `rebuildWidgets` firing the event again) is read from patches and sources, not observed. The Fabric Mixin was not applied.
- **Server compatibility** of a client-only mod against modded servers is reasoned from the handshake sources (NeoForge payload negotiation, Forge channel validation); no modded server was joined. Fabric has no negotiation to cite.
- **Intermediary names** were computed for all 19 obfuscated versions by `intermediary`; the table in 6.1 shows three of them plus the 26.x gap.
- **Class-file major numbers** come from a sample of 50 classes per jar.
- **`code` output** names methods through the mapping of the declaring class; a reference to a member that is not in the mapping keeps its raw name.
- **Versions after 26.3** (snapshot `26.4-snapshot-2` exists in the manifest) were not probed.
