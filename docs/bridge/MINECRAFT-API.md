# Minecraft API reference for Pumpkin Bridge

Last updated: 2026-10-06. Descriptor/source snapshot collected on 2026-10-03 and 2026-10-04 for Minecraft 1.20 through 26.3. These tables explain API changes, not release support or runtime approval. Current support is defined by [`mod/nodes.txt`](../../mod/nodes.txt) and [`mod/verified.json`](../../mod/verified.json); the older proposal nodes below omit many current loaders/releases.

The tables are generated by `tools/mc-api-probe/` from client artifacts and Mojang mappings. Keep their `versions`, `probe-tables`, `breakpoints` and `nodes` markers intact. Regenerate rather than manually changing generated rows; stdout reports are available without rewriting this file.

## 0. API overview

1. **11 API runs between 1.20 and 26.3.** Inside a run no Minecraft member the mod uses changes its signature; between two runs at least one does (section 4). Runs: 1.20-1.20.1 · 1.20.2 · 1.20.3-1.20.4 · 1.20.5-1.21.1 · 1.21.2-1.21.5 · 1.21.6-1.21.8 · 1.21.9-1.21.10 · 1.21.11 · 26.1-26.1.2 · 26.2 · 26.3.
2. **Proposal node snapshot.** Section 5 is generated from `tools/mc-api-probe/nodes.json`, not today's Bridge registry. It is not a recommendation to replace the current 102 registered release/loader cells.
3. **Java:** Mojang requires 17 up to 1.20.4, 21 for 1.20.5 to 1.21.11, 25 from 26.1 (version JSON `javaVersion`; class files of the client jars are major 61, 65, 69).
4. **Render rewrite:** `GuiGraphics` returns `int` from `drawString` up to 1.21.5 and `void` from 1.21.6 (a binary break although the source compiles); `fill` switches to render pipelines at 1.21.6; 26.1 replaces `render(GuiGraphics, ...)` by `extractRenderState(GuiGraphicsExtractor, ...)` and the `Screen`/widget render methods follow.
5. **Input rewrite at 1.21.9:** `keyPressed(int,int,int)` becomes `keyPressed(KeyEvent)`, mouse and character callbacks take event records. `Screen.init(Minecraft,int,int)` loses its `Minecraft` parameter at 1.21.11.
6. **26.2 moves `setScreen`, the current screen and the toast manager from `Minecraft` to `Gui`**; 26.2 also adds `unpublishServer`, 26.3 changes `publishServer` again.
7. **Fabric hook:** `PauseScreen#init()` is declared in `PauseScreen` itself on all 24 probed versions. On obfuscated versions (1.20 to 1.21.11) the Mixin target at runtime is `net.minecraft.class_433#method_25426` (identical on all of them); from 26.1 there is no intermediary and the target is the Mojang name.
8. **NeoForge / Forge hook:** `ScreenEvent.Init.Post` exists and is posted on the game bus (`NeoForge.EVENT_BUS` / `MinecraftForge.EVENT_BUS`) in every NeoForge series from 21.0 to 26.3 and in Forge 1.20.1-47.4.0 and 47.4.26 (section 6).
9. **Mojang's native friends UI appears in 26.2** (`FriendsOverlayScreen`, `FriendToast`, `FriendsButton`, toast id `FRIEND_SYSTEM_NOTIFICATION`). It is absent in 26.1.2; Pumpkin's detached controls must not assume fixed Vanilla widget slots.

## 1. Method and how to re-run

1. The version list is the Mojang version manifest (`piston-meta.mojang.com/mc/game/version_manifest_v2.json`). All 24 requested releases exist: 1.20, 1.20.1 to 1.20.6, 1.21 to 1.21.11, 26.1, 26.1.1, 26.1.2, 26.2, 26.3 (1.20.3, 1.21.3 and 1.21.7 were added to see where a point release changes things). Nothing from the requested list is missing.
2. For each version the tool downloads `client.jar` and `client_mappings` (the official Mojang mapping file) from the manifest entry, checks the SHA-1, and keeps both outside the repository. Versions from 26.1 on are unobfuscated and publish no mapping file.
3. `javap -p -s` reads the classes (JDK 25 reads all of them), the mapping file translates class, method and field names back to Mojang names, and members are resolved through the class hierarchy (superclasses and interfaces), so an inherited method is reported with the class that declares it.
4. `members/ingame.txt` lists what the compat layer needs. A line marked `@used` is called or overridden by the mod; only those decide node boundaries (section 4).
5. `code` reads what a vanilla method calls (`javap -c`), which is how the "how vanilla does it" recipes (section 3.2) were obtained.

For an **ad hoc inspection** from the repository root:

```sh
node tools/mc-api-probe/cli.mjs probe --version 1.21.1 'PauseScreen#init' 'Screen#render' 'Button#builder'
```

That probe prints descriptors; it does not change `tools/mc-api-probe/results/*.json`.
For **document regeneration**, collect the intended releases first, then report from
those persistent results. To refresh this snapshot's full release set:

```sh
node tools/mc-api-probe/cli.mjs collect 1.20 1.20.1 1.20.2 1.20.3 1.20.4 1.20.5 1.20.6 1.21 1.21.1 1.21.2 1.21.3 1.21.4 1.21.5 1.21.6 1.21.7 1.21.8 1.21.9 1.21.10 1.21.11 26.1 26.1.1 26.1.2 26.2 26.3
node tools/mc-api-probe/cli.mjs report --doc docs/bridge/MINECRAFT-API.md
```

`report` reads collected JSON and the tool's `nodes.json`; it does not rerun `javap`.
For another release set, replace the `collect` arguments. A custom results directory
needs the same `--out <directory>` on both commands.

Collection, cache and JDK details are in [the tool README](../../tools/mc-api-probe/README.md). This reference does not prescribe owner test tasks.

## 2. Reading the tables

Section 3 has one table per member group. Columns are **eras**: consecutive versions in which every member of the group has the same signature.

| Symbol / notation | Meaning |
| --- | --- |
| `access (parameters) → return type` | The member's signature in that era |
| `=` | Same as the column to the left |
| `–` | Member does not exist |
| `class absent` | Class does not exist in that era |
| `← X` | Superclass or interface that declares an inherited member |
| Simple class names | Short display names, not fully qualified descriptors |

Private members are left out. Full descriptors with fully qualified Mojang names are in
[`tools/mc-api-probe/results/<version>.json`](../../tools/mc-api-probe/results/) and are also
printed by the [`probe` command](#1-method-and-how-to-re-run).

The binary descriptor includes the return type. A call compiled against `int drawString(...)` throws `NoSuchMethodError` on a version where the method returns `void`, so return-type changes count as breaks.

### 3.1 Notes on the tables

- **`Screen#init`:** `protected void init()` is the override point in every era. `Screen.init(Minecraft,int,int)` (public final, called by the game) became `init(int,int)` in 1.21.11; the mod never calls it.
- **`Screen#resize`:** vanilla re-runs `init()` (through `rebuildWidgets`) on resize, or `repositionElements()` once initialized. Those methods are signature-stable in the 24-version snapshot; `resize` loses its `Minecraft` parameter in 1.21.11. Compatibility code must use the correct override for each API era.
- **`Screen#mouseScrolled`:** three parameters up to 1.20.1, four from 1.20.2 (horizontal delta added). A scroll override is a node boundary at 1.20.2.
- **Toasts:** up to 1.20.2 the toast id is the enum `SystemToast.SystemToastIds` (use the constant `PERIODIC_NOTIFICATION`; no own id possible). From 1.20.3 `SystemToast.SystemToastId` is a class with public constructors (`()` and `(long displayTime)`), so the mod can own one id. From 1.21.2 the manager is `ToastManager` (`Minecraft.getToastManager()`), from 26.2 `Gui.toastManager()`.
- **`Checkbox`:** no builder in 1.20 to 1.20.2 (constructor only). The builder exists from 1.20.3.
- **`EditBox`:** the six-argument constructor `(Font,int,int,int,int,Component)` exists in all 24 versions; the other constructors are additions.
- **Scrolling list (`AbstractSelectionList`):** constructor, render, scroll and entry methods change frequently. Pumpkin's own widget/layout layer avoids treating this class as a stable cross-version ABI.
- **Mojang friends (26.2+):** `FriendToast`, `FriendsButton`, `FriendsOverlayScreen` and `FRIEND_SYSTEM_NOTIFICATION` appear in 26.2. Detached controls must use available space, not fixed Vanilla slots.
- **Additional context members:** `PauseScreen#showsPauseMenu` appears in 1.20.2. `Checkbox.Builder#maxWidth` appears in 1.21 and is not marked `@used`; Pumpkin sizes toggles itself. `FriendToast#add` and `ResolvableProfile#createUnresolved` are context, not permission to reuse Mojang's friend toast.

### 3.2 How vanilla does the three world operations (read with `code`)

**Leave the world** (what the pause menu button does; the mod needs this before `joinHere`):

| Versions | Sequence in vanilla (`PauseScreen` or `Minecraft`) | Checked on |
|---|---|---|
| 1.20 – 1.20.1 | `ClientLevel.disconnect()`; `Minecraft.clearLevel(Screen)` (singleplayer, `GenericDirtMessageScreen`) or `Minecraft.clearLevel()`; then `setScreen(TitleScreen)` | 1.20, 1.20.1 |
| 1.20.2 – 1.21.5 | `ClientLevel.disconnect()`; `Minecraft.disconnect(Screen)` (singleplayer, `GenericMessageScreen`) or `Minecraft.disconnect()`; then `setScreen(TitleScreen)` | 1.20.2, 1.20.5, 1.21.1, 1.21.2, 1.21.5 |
| 1.21.6 – 1.21.8 | static `PauseScreen.disconnectFromWorld(Minecraft, Component)` = `ClientLevel.disconnect(Component)`; `Minecraft.disconnectWithSavingScreen()` (local server) or `disconnectWithProgressScreen()`; then `setScreen(TitleScreen)` | 1.21.6, 1.21.8 |
| 1.21.9 – 26.3 | public `Minecraft.disconnectFromWorld(Component)` does all of it; 26.2 and later end with `Gui.setScreen` | 1.21.9, 1.21.11, 26.3 |

`ClientLevel.DEFAULT_QUIT_MESSAGE` (static `Component`) exists from 1.21.6. The compat call `Disconnect.leaveWorld()` is therefore four implementations, not one.

**Publish to LAN:** `ShareToLanScreen` (1.20 to 26.1.2) calls `IntegratedServer.publishServer(GameType, boolean allowCommands, int port)` with `HttpUtil.getAvailablePort()`. 26.2 changes it to `publishServer(MinecraftServer.MultiplayerScope, GameType, boolean, int)` plus `publishServer(MultiplayerScope, int)`, 26.3 to `publishServer(MultiplayerScope, boolean, int)`; both pass `MultiplayerScope.LAN`. `ShareToLanScreen` is gone in 26.2 (replaced by `WorldOptionsScreen` in 26.3, which also calls `unpublishServer()`). `isPublished()` and `getPort()` exist in all 24 versions.

**Unpublish** (`IntegratedServer.unpublishServer()`, returns `boolean`) exists only from 26.2. Earlier Vanilla versions cannot close a published LAN world without leaving it.

**Connect:** `ConnectScreen.startConnecting(Screen, Minecraft, ServerAddress, ServerData, boolean)` up to 1.20.4; a sixth parameter `TransferState` from 1.20.5 (pass `null`). `ServerData(String,String,boolean)` up to 1.20.1, `ServerData(String,String,ServerData.Type)` from 1.20.2 (`ServerData.Type.OTHER`).

## 8. Evidence limits

- This snapshot is class-file/source evidence, not proof that every target compiles, starts or renders. Current production/runtime records live with the mod, not in these tables.
- An incomplete/stale `@used` member set can change inferred API boundaries.
- Metadata-derived loader floors do not prove lowest-loader startup. Later-series beta behavior is not implied by a numeric minimum.
- Loader hook and server-compatibility reasoning was read from patches/handshake sources; it does not establish modded-server interoperability.
- Class-file major numbers were sampled from fifty classes per JAR. Unmapped bytecode references retain raw names in `code` output.
- Releases below 1.20 and after 26.3 are outside this descriptor snapshot even though some older releases are present in the current Bridge registry.
